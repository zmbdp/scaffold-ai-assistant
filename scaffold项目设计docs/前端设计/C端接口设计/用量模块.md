# C 端接口设计 - 用量模块

> 公共约定（网关地址、认证机制、响应结构、错误码、日期格式等）见 [./总说明.md](./总说明.md)。

## 功能介绍

用量模块提供 C 端用户查询自身 AI 调用用量数据的能力，对应后端 `UserUsageController`（前缀 `/user/usage`，前端经网关访问 `/portal/user/usage/**`）。

主要使用场景：
- **仪表盘**：展示当前用户的累计 Token 消耗、今日消耗、对话数、活跃天数、近 7 天趋势
- **用量管理页顶部卡片**：与仪表盘共用同一接口，展示汇总数据
- **用量管理页表格**：分页展示当前用户的 AI 调用明细（提问摘要、模型、Token、耗时、时间）

> 后端实现：portal-service 通过 Feign 调用 chat-service 的 `StatisticsApi`，数据来源为 `sys_ai_operation_log` 表（与 B 端统计接口共用同一张表，按 `user_id` 过滤聚合）。

## 1. 获取当前用户用量汇总

**接口**：`GET /portal/user/usage/summary`

**认证**：需要 C 端 JWT（`userFrom=app`）

**限流 / 幂等**：无

**Content-Type**：无（GET 请求）

### 请求参数

无（userId 由后端从 JWT 解析，**前端禁止传 userId**，防越权）。

### 请求示例

```
GET /portal/user/usage/summary
Authorization: Bearer {accessToken}
```

### 响应结构 `Result<UsageSummaryVO>`

| 字段 | Java 类型 | 前端类型 | 含义 | 数据来源 |
| --- | --- | --- | --- | --- |
| `totalTokens` | Long | number | 累计 Token 消耗 | `SUM(sys_ai_operation_log.total_tokens) WHERE user_id = ? AND status = 'SUCCESS'` |
| `todayTokens` | Long | number | 今日 Token 消耗 | 同上 + `AND create_date = 今日(YYYYMMDD)` |
| `totalConversations` | Long | number | 对话总数 | `COUNT(DISTINCT conversation_id) WHERE user_id = ? AND conversation_id IS NOT NULL` |
| `todayConversations` | Long | number | 今日对话数 | 同上 + `AND create_date = 今日` |
| `activeDays` | Integer | number | 活跃天数 | `COUNT(DISTINCT create_date) WHERE user_id = ?` |
| `firstUsedTime` | Long | number | 首次使用时间（毫秒时间戳） | `MIN(create_time) WHERE user_id = ?`（用于"使用第 N 天"等展示） |
| `trendData` | `List<TrendData>` | array | 近 7 天每日 Token 趋势 | `GROUP BY DATE(create_time)` 近 7 天，无数据日期补 0 |

`trendData` 数组元素结构 `TrendData`：

| 字段 | Java 类型 | 前端类型 | 含义 |
| --- | --- | --- | --- |
| `date` | String | string | 日期（格式：`yyyy-MM-dd`，如 `2026-07-20`） |
| `count` | Long | number | 当日 Token 消耗（无调用时为 `0`） |

> `trendData` 固定返回近 7 天数据（含当天），按日期升序排列，无调用记录的日期 `count` 为 `0`，确保趋势图连续。

### 响应示例

```json
{
  "code": 200000,
  "errMsg": "操作成功",
  "data": {
    "totalTokens": 152340,
    "todayTokens": 8650,
    "totalConversations": 42,
    "todayConversations": 6,
    "activeDays": 12,
    "firstUsedTime": 1784900000000,
    "trendData": [
      { "date": "2026-07-20", "count": 3200 },
      { "date": "2026-07-21", "count": 0 },
      { "date": "2026-07-22", "count": 5400 },
      { "date": "2026-07-23", "count": 2100 },
      { "date": "2026-07-24", "count": 4300 },
      { "date": "2026-07-25", "count": 6700 },
      { "date": "2026-07-26", "count": 8650 }
    ]
  }
}
```

### 业务说明

- **userId 提取**：portal-service 从当前请求 JWT 解析 `userId` 后通过 Feign 传给 chat-service，前端无需（也禁止）传 `userId`，避免越权查询他人数据。
- **数据来源**：`sys_ai_operation_log` 表（AI 调用链路日志表），按 `user_id` 过滤聚合。Token 消耗统计仅包含 `status='SUCCESS'` 的成功调用；对话数和活跃天数统计包含所有状态的记录。
- **firstUsedTime 字段**：`app_user` 表无注册时间字段，这里用该用户首次 AI 调用时间近似作为"使用起点"，用于前端计算"使用第 N 天"等展示。
- **缓存策略**：后端对该接口结果做 Redis 缓存，TTL = 60 秒（用户级数据更新频率高，TTL 设短一些保证时效性）。缓存 key 格式：`stats:user_usage:summary:{userId}`。
- **日期格式**：`todayTokens` / `todayConversations` 按 `create_date` 字段（BIGINT，格式 `YYYYMMDD`，与脚手架统一）匹配当天日期。

### 错误码

| code | errMsg | 场景 |
| --- | --- | --- |
| `401000` / `401001` / `401003` | 见总说明 | token 缺失 / 无效 / 登录态过期（网关校验） |
| `400000` | 无效的参数 | Service 层解析 JWT 失败（`用户令牌有误`） |
| `500001` | 操作失败 | Feign 调用 chat-service 失败或返回非成功（`查询用户用量汇总失败`） |

## 2. 获取当前用户用量明细（分页）

**接口**：`GET /portal/user/usage/list`

**认证**：需要 C 端 JWT（`userFrom=app`）

**限流 / 幂等**：无

**Content-Type**：无（GET 请求）

### 查询参数

| 参数 | Java 类型 | 前端类型 | 必传 | 校验规则 | 默认值 | 含义 |
| --- | --- | --- | --- | --- | --- | --- |
| `pageNo` | Integer | number | 否 | 为空或 ≤ 0 时使用默认值 | `1` | 页码 |
| `pageSize` | Integer | number | 否 | 为空或 ≤ 0 时使用默认值 | `10` | 每页条数 |

> userId 由后端从 JWT 解析，**前端禁止传 userId**，防越权。

### 请求示例

```
GET /portal/user/usage/list?pageNo=1&pageSize=10
Authorization: Bearer {accessToken}
```

### 响应结构 `Result<BasePageVO<UsageItemVO>>`

`BasePageVO` 字段：

| 字段 | Java 类型 | 前端类型 | 含义 |
| --- | --- | --- | --- |
| `totals` | Integer | number | 记录总数 |
| `totalPages` | Integer | number | 总页数 |
| `list` | `List<UsageItemVO>` | array | 当前页数据列表 |

`UsageItemVO` 字段：

| 字段 | Java 类型 | 前端类型 | 含义 | 数据来源 |
| --- | --- | --- | --- | --- |
| `operationId` | Long | number | AI 操作日志 ID | `sys_ai_operation_log.id` |
| `conversationId` | Long | number | 会话 ID | `sys_ai_operation_log.conversation_id` |
| `question` | String | string | 用户提问摘要 | `LEFT(sys_ai_operation_log.prompt, 50)`（截前 50 字符） |
| `model` | String | string | 模型名 | `sys_ai_operation_log.model` |
| `tokenUsage` | Integer | number | 本次 Token 消耗 | `sys_ai_operation_log.total_tokens` |
| `duration` | Integer | number | 耗时（毫秒） | `sys_ai_operation_log.response_time` |
| `createTime` | Long | number | 调用时间（毫秒时间戳） | `UNIX_TIMESTAMP(create_time) * 1000` |

### 响应示例

```json
{
  "code": 200000,
  "errMsg": "操作成功",
  "data": {
    "totals": 42,
    "totalPages": 5,
    "list": [
      {
        "operationId": 1785000000000000001,
        "conversationId": 1784900000000000001,
        "question": "请帮我分析一下这份简历的优缺点，并给出改进建议。",
        "model": "deepseek-v4-flash",
        "tokenUsage": 1520,
        "duration": 3250,
        "createTime": 1785000000000
      },
      {
        "operationId": 1785000000000000002,
        "conversationId": 1784900000000000001,
        "question": "如何用 Spring AI 实现 RAG 检索增强？",
        "model": "deepseek-v4-flash",
        "tokenUsage": 980,
        "duration": 2100,
        "createTime": 1784999999000
      }
    ]
  }
}
```

### 业务说明

- **userId 提取**：与汇总接口一致，portal-service 从 JWT 解析 `userId` 后通过 Feign 传给 chat-service。
- **数据来源**：`sys_ai_operation_log` 表，按 `user_id` 过滤，按 `create_time` 倒序分页返回。
- **排序规则**：`create_time DESC`（最新的调用记录排在最前）。
- **prompt 截断**：`question` 字段取 `prompt` 前 50 字符作为提问摘要，避免传输完整 prompt 影响性能。前端如需查看完整内容，可点击行进入会话详情（走历史模块接口）。
- **不缓存**：明细列表实时性要求高，且分页参数多变，每次查询直接走数据库。
- **conversationId 字段**：可能为 `null`（非对话类 AI 调用，如 Embedding/Rerank 操作），前端展示时需做 null 判断。

### 错误码

| code | errMsg | 场景 |
| --- | --- | --- |
| `401000` / `401001` / `401003` | 见总说明 | token 缺失 / 无效 / 登录态过期（网关校验） |
| `400000` | 无效的参数 | Service 层解析 JWT 失败（`用户令牌有误`） |
| `500001` | 操作失败 | Feign 调用 chat-service 失败或返回非成功（`查询用户用量明细失败`） |

## 前端注意事项

1. **越权防护**：两个接口都**不需要传 `userId`**，后端从 JWT 解析。前端如果误传 `userId` 参数会被后端忽略（Controller 没有接收该参数）。
2. **汇总接口缓存**：60 秒 Redis 缓存，用户刚发起一次 AI 对话后立即查询汇总，可能看到的还是旧数据（最多 60 秒延迟）。如需强制刷新，前端可加"刷新"按钮（重复请求即可触发缓存到期后的重新查询）。
3. **趋势图渲染**：`trendData` 固定返回 7 天数据（含当天），按日期升序，无数据日期 `count=0`，前端可直接渲染为连续折线图，无需自行补全缺失日期。
4. **明细表格分页**：使用 `pageNo` / `pageSize` 参数（与脚手架统一），响应使用 `totals` / `totalPages` / `list` 字段。`pageNo` 超出 `totalPages` 时返回空列表（不报错）。
5. **提问摘要展示**：`question` 字段已截前 50 字符，前端可加省略号样式；完整提问内容需进入会话详情查看（走 `/portal/history/{sessionId}` 接口）。
6. **空数据处理**：
   - 新用户从未发起 AI 调用：`totalTokens=0`、`todayTokens=0`、`totalConversations=0`、`todayConversations=0`、`activeDays=0`、`firstUsedTime=null`、`trendData` 仍返回 7 天数据（全为 0）。
   - 明细列表无数据：`totals=0`、`totalPages=0`、`list=[]`。
7. **时间字段处理**：`firstUsedTime` 和 `createTime` 均为毫秒时间戳（13 位），前端可直接 `new Date(timestamp)` 转换显示。
